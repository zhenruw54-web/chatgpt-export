# V0.2 single-conversation pilot: hard safety gate

Status: IMPLEMENTED IN 0.6.59.4 CANDIDATE — NOT INSTALLED, NO REAL EXPORT RUN.
2026-11-17. This document is a small acceptance gate within the existing
ChatGPT Export V0.2 extension; it is not another archive product.

## Grounded current behavior

- Background `cgxV02Run()` requests `cgx-v02-auto-export` with
  `conversationLimit: 0`; the content script resets this value to 0.
- Current `exportAll()` scans the full list and processes **all changed**
  entries, provided the delta count is no greater than 10.
- Current popup's `Only the 1 most recent` applies to the legacy
  `cgx-export-all` path. It does not exercise the V0.2 browser download
  acknowledgement and incremental commit behavior.
- The latest observed V0.2 read-only preview was 67 unique, 2 new,
  5 modified (7 total); those numbers are time-sensitive, not a whitelist.
- The V0.2 scheduled path currently commits its updated index **after Edge
  reports the ZIP complete but before V0.1 acknowledges valid ingestion**.
  A ZIP subsequently missing/corrupt on disk could make a conversation appear
  processed. This is an unresolved production safety blocker.

## Minimal controlled pilot — required implementation before a real download

1. Introduce a **test-only, explicitly invoked** single-target operation.
   Do NOT change the 23:45 scheduled export defaults, legacy manual-export
   behavior, historical 65-item baseline, extension ID, or regular 10-item cap.
2. User picks one *non-sensitive* genuinely new conversation by its stable
   conversation/workspace key from the locally scanned delta list. Do not
   pick by title, date, list position, or an assumed 'latest' ordering.
   Keep real keys, raw content and credentials out of logs and GitHub.
3. Gate on verified 65-item migration receipt, 2 shared aliases, scheduler
   OFF, the selected key being absent from the prior index, and exactly one
   local selection. Reject ambiguous workspace identity or changed baseline.
4. Independently rescan just before export. Build a changed-item list using
   the **same** fingerprint algorithm as the read-only preview. Require
   exactly one selected target, precise key match, and full changed-list
   count <= 10. Stop on stale or unexpected changes. Ensure that
   `selectedItems.length === 1` immediately before ZIP creation, and
   `manifest.conversation_count === 1` afterwards.
5. Preserve V0.2 media, Markdown, raw JSON, checksums and Edge
   `downloads` acknowledgement path. Do not silently switch to
   `cgx-export-all`, `cgx-export-current` or `items.splice(1)`.
6. **Do not advance the real index at mere browser download completion.**
   A pilot may use a disposable extension profile / test storage to
   prove the legacy commit path, OR add a durable pending-receipt mechanism.
   For any real V0.2 user index, only commit the selected key after
   independently verified ZIP CRC, SHA-256 manifest and V0.1 import receipt,
   leaving all other changed keys untouched. Stop if this handshake
   is not available; do not claim full archive success.
7. First simulate cancellation, interrupted download, changed target,
   wrong key, no target and multiple targets; confirm **zero ZIP and zero
   index mutation** for every rejection. Then simulate byte mismatch,
   failed attachments, worker restart and aborted download.
8. Real pilot is one isolated small ZIP with one unimportant test chat.
   Verify only its ZIP/manifest and V0.1 copied test baseline;
   never re-download historical 4.3GB, never use customer data.
9. Require Windows true exit codes, test counts and extension screenshots
   in the acceptance report. No 'PASS' based on syntax/static/mock tests
   alone. Keep 23:45 schedule OFF and R22/F-drive untouched.

## Next action

The isolated 0.6.59.4 candidate adds a test-only flow with these states:

1. exact conversation/workspace target check with no download;
2. independent rescan and one-conversation ZIP download acknowledgement;
3. durable `browser_download_complete_v01_pending` receipt with no real-index write;
4. local ZIP/V0.1 test-copy verification using
   `tools/verify_v02_pilot_receipt.py`;
5. atomic commit of only the selected index key after the matching local receipt.

The ordinary 23:45 path, legacy manual export and migration flow are unchanged.
No permission to replace the user's installed 0.6.59.3 extension or perform a
real export is implied by this candidate implementation.
