# V0.2 Edge Scheduled Export — Development Checkpoint

Status: **CODE DRAFT / NO WINDOWS ACCEPTANCE / AUTOMATION DISABLED**

Upstream: thekester/chatgpt-export 0.6.59, MIT. This is an independent
development branch. Do not merge into `main` or replace an existing Edge
extension before index migration and Windows validation.

## Scope

- Reuse the existing `cgx-export-all` export engine via a safe
  `cgx-v02-auto-export` message.
- Add an opt-in 23:45 **Asia/Shanghai** daily browser alarm.
- Recreate missed alarms on Edge startup/worker start; a sleeping or closed
  machine cannot be woken up by the extension.
- Never request ChatGPT conversation deletion in scheduled mode.
- Always export Markdown, raw JSON, images, attachments, SHA-256 checksums.
- Incremental export only; a missing `cgx-export-index` blocks enable.
- Do not touch the frozen V0.1 ZIP processor, R22, Google Drive, or F: vault.
- Report export-engine completion separately from verified download/durable
  disk storage. This version does **not** verify ZIP persistence on Windows.

## Critical migration gate

The existing installed Edge extension and this unpacked development extension
will normally have **different extension IDs**. Their
`chrome.storage.local` namespaces are separate. In particular, the previous
`cgx-export-index` does not silently carry over.

An empty index would cause a second full account export; for this reason the
V0.2 switch is disabled if `cgx-export-index` is absent.

**Do not synthesize or overwrite a baseline without evidence.** The test branch now provides a local import UI (old-extension index JSON plus
V0.1 baseline-ID JSON). It refuses to enable scheduled export unless all 65
verified V0.1 IDs are present and the imported index has valid upstream SHA-256
fingerprints. The user must still obtain authentic local files from the
old extension and V0.1 baseline before performing the actual migration.
See `docs/V0.2_INDEX_MIGRATION.md`. A bare set of 65 conversation IDs is **not** equivalent to
the upstream extension's fingerprint index.

## Read-only V0.1 baseline handoff (latest)

- `tools/export_v01_baseline_ids.py`: separate read-only SQLite tool; refuses
  missing/mismatched schema, non-65 baseline count, duplicate IDs, and
  overwriting an existing JSON. Selects only `versions.kind='baseline'`,
  not subsequent incremental/synthetic records.
- `tests/test_v01_baseline_export.py`: standalone Python unittest fixtures.
- The DB schema was inferred by inspecting an accessible **V0.1 test package**
  and is checked again on the real database; we have not accessed the user's
  frozen 65-chat SQLite file or executed these Python tests on Windows.
- Use `python` from an installed interpreter; the Windows `py` launcher
  was absent in a previously observed environment.

## Migration implementation and tests

- Local migration handler in `src/background.js` and two-file popup import.
- Strict input schema, 65 unique V0.1 ID coverage, 64-hex fingerprints.
- Refuse when old index is absent, invalid, incomplete, or target already exists.
- Receipt rechecked on each scheduler activation; no silent fallback.
- Local mock tests for the migration and timer guards (12/12 in V8 model
  simulation); repeatable developer test source:
  `tests/v02_migration_smoke.js`.
- **Not yet tested on the real user's original extension, Windows Edge, or
  the frozen V0.1 database. No real baseline migration has happened.**

## Security and acceptance

- No new broad host permissions; only existing ChatGPT host permissions are used.
- No user conversation data, screenshots, tokens or files may be committed.
- No automatic cleanup of source ZIPs or ChatGPT conversations.
- No automatic full export while the baseline is absent.
- Handle concurrent triggers without double processing.
- Test actual Edge timer firing, login failure, empty delta, one new/one changed
  conversation, images/attachments, restart after missed schedule, download
  integrity, and interoperability with V0.1.
- Distinguish **export completed in ChatGPT tab** from a ZIP fully downloaded and
  accepted by V0.1.
- Existing 65-conversation baseline remains immutable.
